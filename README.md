# 台本どおり字幕メーカー

動画と台本を入れると、**台本どおりの文字**で、**話しているタイミングに合った**字幕ファイル（SRT）を作る Web アプリです。

- 音声認識（Whisper）は**タイミングを知るためだけ**に使い、字幕の**文字は台本から取ります**。「Claude Code」が「クロードコード」になるような聞き間違いは字幕に出ません。
- **ブラウザだけで動きます。** サーバー・API キー・アカウントは不要です。
- **動画・音声・台本は端末の外に出ません。** ネットに出ていく通信は、初回の音声認識モデルのダウンロード（Hugging Face から）だけです。モデルはブラウザに保存され、2回目からはダウンロードしません。

## 使い方

1. 動画（mp4 / mov）か音声（wav / m4a / mp3）を、左上の枠にドラッグ＆ドロップ（クリックして選んでも可）
2. 台本を貼る（ふつうの文章でOK。段落があってもよく、字幕の区切りを入れる必要はありません）
3. 「③ 字幕を作る」を押す
   - 初回だけモデル（約320MB）をダウンロードします。進み具合はバーと文字で出ます
   - 聞き取り中は「何個目の区間か・あと何分か」が出ます。画面は固まりません
4. 右の一覧で確認・修正する
   - 行（番号や時刻のあたり）をクリックすると、その場面から再生されます
   - 文字はその場で直せます。改行もそのまま字幕の改行になります
   - 開始・終了は「−」「＋」で 0.1 秒ずつ動かせます
   - 「分割」はカーソルの位置（カーソルが無ければ改行の位置）で2枚に分けます。「結合↓」は次の字幕とつなげます
   - 直した内容は、すぐに左のプレビューと書き出しに反映されます
5. 「④ 書き出す」で SRT / VTT / テキストを保存（ファイル名は入れた動画の名前に合わせます）

### 色の意味

| 色 | 意味 |
|---|---|
| 白 | 台本どおり |
| 黄 | 台本と音声が違うかも（読み違い・言い直し・聞き取れなかった所）。字幕にはします |
| 赤 | 読まれていない文。**字幕にはしません**（一覧には残します） |
| 紫 | 台本にない発話（アドリブ・言い直し）。聞き取った文字を参考に出します。**字幕にはしません** |

設定の「1行の字数」「行数」「文末の『。』を消す」を変えたら、もう一度「字幕を作る」を押すと、聞き取りをやり直さずに（数秒で）作り直します。

台本を空のまま「字幕を作る」を押すと、聞き取った文字で字幕を作ります（比較用）。

## 起動（開発）

```sh
npm install
npm run dev
```

表示された URL（例 `http://localhost:5173/`）を Mac の Chrome で開きます。

## GitHub Pages への置き方

`npm run build` でできる `dist/` は、すべて相対パスで参照しているので、どのサブパス（`https://<user>.github.io/<repo>/`）に置いても動きます。

**A. GitHub Actions で自動公開（おすすめ）**

1. このフォルダを GitHub のリポジトリに push する（ブランチ `main`）
2. リポジトリの Settings → Pages → Build and deployment の Source を **GitHub Actions** にする
3. 同梱の `.github/workflows/deploy.yml` が `npm ci && npm run build` をして `dist/` を公開します
4. `https://<user>.github.io/<repo>/` を開く

**B. 手で置く**

```sh
npm run build
# dist/ の中身を gh-pages ブランチ（または Pages の公開フォルダ）にそのままコピーして push
```

手元でサブパス配信を試すには `node checks/serve.mjs dist 4173` で `http://localhost:4173/subtitle-maker/` を開きます。

## 既定モデルとその理由

既定は **`onnx-community/whisper-small_timestamped`**（WebGPU では encoder fp16 ＋ decoder q4f16、約320MB）です。選べるモデルは次の3つです。

| モデル | ダウンロード | 1分の動画の処理（M1・Chrome・WebGPU） | 日本語の聞き取り | 字幕の開始時刻 |
|---|---|---|---|---|
| base | 約110MB | 速い | 「一晩→人番」「寝ている→ネテイル」など誤りが多い | 1分の素材で 21 枚中 1 枚が 1 秒ずれた |
| **small（既定）** | 約320MB | 約22秒（9分23秒の本編は約2分40秒） | 固有名詞以外はほぼ正しい | large-v3-turbo と 159 枚すべて同じ |
| large-v3-turbo | 約1.5GB | 遅い・メモリを多く使う | いちばん正確（英語も英字で出る） | 基準 |

- このアプリでは聞き取りの文字は字幕に使わず、**台本と照らし合わせて時刻を取るため**だけに使います。照合が安定するだけの精度があれば十分で、small は本編 9分23秒 の全 159 枚で large-v3-turbo と開始時刻が一致しました（`checks/compare.mjs`）。
- base は速いものの、聞き間違いが多い所で照合の手がかりが減り、時刻がずれる字幕が出ました。
- large-v3-turbo はダウンロードが約5倍で、初回の待ち時間とブラウザの保存容量の負担が大きいわりに、このアプリの結果（時刻）はほとんど変わりません。
- 単語ごとの時刻（クロスアテンションの DTW）を出せる `_timestamped` 版が必要なため、この3つから選んでいます。

## しくみ

1. ブラウザの中（Web Audio の `decodeAudioData`）で、動画・音声から 16kHz モノラルの音声を取り出す
2. 音量の包絡線から静かな所を探し、30秒以内の区間に切る（無音だけの区間は飛ばす）
3. Web Worker の中で Whisper（Transformers.js、WebGPU。無ければ WASM）を動かし、トークンごとの時刻を得る
   - 声があるのに文字が出なかった所（Whisper の読み飛ばし）は、そこだけもう一度聞き取る
4. 台本と聞き取りの文字を、かな・英数字を正規化してから1文字ずつ対応づける（アフィンギャップの大域アラインメント）
5. 台本を文に分け、句読点・文節（助詞のあと）で字幕1枚（最大2行×16字）に分ける。英単語・カタカナ語・「12個」のような数字＋助数詞の途中や、行頭の「、。）」などでは切らない
6. 字幕の開始は「完全に一致した文字」の時刻から求め、直前に間があれば**声が立ち上がる瞬間**に合わせる。終了は話し終わり（次まで短ければ次の開始まで）。0.8〜7秒・重なりなしにそろえる
7. 文ごとの一致率から「読まれていない」「違うかも」を、聞き取りにしかない文字のまとまりから「台本にない発話」を出す

同じ入力なら同じ字幕になります（貪欲法で、区間どうしの文脈を使わないため）。

## できないこと・苦手なこと

- **Mac の Chrome（最新版）向け**です。Safari・Firefox では試していません。WebGPU が無い環境では WASM で動きますが、かなり遅くなります（数倍〜10倍程度）。
- 初回はモデルのダウンロード（約320MB）が必要です。オフラインでの初回利用はできません。
- **BGM が声と同じくらい大きい**、複数人が同時に話す、といった音声では、時刻の精度が落ちます（話し始めの検出に音量を使うため）。
- 台本と大きく違う話し方（アドリブが多い・順番を入れ替えて読む）は苦手です。入れ替えた文は「読まれていない」「台本にない発話」として出ます。
- 字幕の文字は台本のままなので、**言い直しやアドリブは字幕になりません**（紫の行で知らせます。必要なら一覧で手で足してください）。
- 「。」「、」が無く、とても長い文は、助詞のあとなどで切りますが、切れ目が不自然になることがあります。
- 1つの文が7秒より長く1枚に収まる場合などは、表示時間を7秒で打ち切ります。
- 長い動画（1時間以上）は、ブラウザのメモリを多く使います。
- 「読まれていない」の判定は文単位です。文の一部だけを読み飛ばした場合は、黄色（違うかも）になることがあります。

## 検証用スクリプト（`checks/`）

アプリの動作に必要なものではありません。合格基準（`acceptance.json`）の確認に使ったものです。

- `checks/serve.mjs` … `dist/` を `/subtitle-maker/` のサブパスで配る静的サーバー
- `checks/e2e.mjs` … Chrome（headless・WebGPU）でアプリを操作して、字幕を作り・書き出し・通信を記録する
- `checks/e2e-edit.mjs` … 一覧のクリック再生・修正・±0.1秒・分割・結合の確認
- `checks/run-asr.ts` / `checks/build-check.ts` … Node で同じ処理を動かし、字幕のルール（字数・行数・禁則・表示時間・重なり・台本の文字だけか）を機械的に確かめる
- `checks/compare.mjs` / `checks/onsets.ts` / `checks/snapped.ts` … 開始時刻の比較・確認
